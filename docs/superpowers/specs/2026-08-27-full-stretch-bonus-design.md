## Distributed circuit breaker

Create `SharedRedisCircuitBreaker` in a focused module. It exposes the same behavioral surface used by the gateway: `call`, `allow_request`, `record_success`, `record_failure`, `state`, and `transition_log`.

Each provider uses a Redis namespace containing:

- `state`: `closed`, `open`, or `half_open`.
- `failures`: consecutive failure counter.
- `successes`: half-open success counter.
- `opened_at`: wall-clock timestamp used across processes.
- `probe_lease`: a short lease used to guarantee at most one HALF_OPEN probe across instances.
- `transitions`: shared transition evidence.

Failure counting uses Redis `INCR` plus `EXPIRE`. Opening a circuit writes shared `state=open` and `opened_at`. Once the reset timeout passes, only the instance that acquires `probe_lease` using `SET ... NX` may move the circuit to HALF_OPEN and issue the recovery probe. Probe success closes the shared circuit; probe failure reopens it.

Two independently constructed breakers using the same provider namespace must immediately observe one another's OPEN/CLOSED state after synchronization through Redis.

## Cost-aware routing

Add a `CostBudget` policy object with:

- `limit`: maximum configured spend.
- `switch_ratio`: default `0.8`.
- `spent`: accumulated provider spend.
- thread-safe accounting for concurrent requests.

Routing behavior after cache lookup:

- Usage `< 80%`: preserve configured provider order.
- Usage `>= 80%` and `< 100%`: try providers ordered by `cost_per_1k_tokens`, cheapest first.
- Usage `>= 100%`: do not call a paid provider; return `static_fallback` with `error="budget_exhausted"`.

A successful provider response records its actual `estimated_cost`. If a request starts below 100% and pushes spend beyond the limit, that completed request is retained; following cache misses are blocked.

When the cheaper backup provider is chosen first in constrained mode, its route remains `fallback` because route labels describe provider role rather than iteration position.
